Warning Identity

Default minimum password length is 8

Modern baselines start at 12–15, plus ban-list / Windows Hello / gMSA for services.

Why it matters. Length beats complexity theater. Fine-grained policies can raise length for admins first.
What to do next. Review Default Domain Policy and any FGPP before you tighten anything — you can lock out service accounts.
Warning Identity

Account lockout threshold is 0 (never lock out)

Brute-force password guesses never lock the account.

Why it matters. A threshold of 0 is sometimes kept to avoid DoS lockouts. Know which it is.
What to do next. Prefer smart lockout (Azure) or a modest threshold plus a short observation window.
Warning Identity

krbtgt password is 640 days old

krbtgt is the account that encrypts Kerberos TGTs. A stolen hash remains useful until this password is rotated twice.

Why it matters. Microsoft guidance is a two-stage reset (then wait for replication / ticket lifetime, then reset again).
What to do next. Use Microsoft KRBTGT reset guidance. Never treat this as a casual Set-ADAccountPassword.
Warning Identity

Administrator, j.blake, s.patel, helpdesk.admin, vendor.temp, backup.svc

Why it matters. DA is the keys to the domain. Broad membership is the most common inherited-domain smell.
What to do next. Inventory each member, move day-to-day work to lesser groups, and keep DA for DC/domain work only.

FSMO means "this write can only happen in one place"

Most AD writes replicate multimaster. Five operations do not. If you inherit a domain, memorize the holders and keep them on DCs you would actually answer a page for.

Forest FSMO

Schema Master

NW-DC01.northwind.lab

The only DC that can write to the AD schema (new classes and attributes).

Schema updates are rare (Exchange, AD Connect, Windows functional-level raises) but they must succeed.

Keep it on a healthy, well-connected hub DC. Treat schema extensions as change-controlled events.
Forest FSMO

Domain Naming Master

NW-DC01.northwind.lab

The only DC that can add or remove domains and application partitions.

Idle most of the time. Required when creating domains, trusts that add partitions, or some DNS app partitions.

Usually colocated with Schema Master. Confirm it is reachable from wherever you would run domain-create tools.
Domain FSMO

PDC Emulator

NW-DC01.northwind.lab

Password changes and lockouts, time source for the domain, GPO editing target, backward-compat PDC.

This is the FSMO you will feel immediately if it is down: logons, lockouts, and time drift.

Put it on your most reliable, lowest-latency DC. Clients and other DCs sync time from here (directly or indirectly).
Domain FSMO

RID Master

NW-DC01.northwind.lab

Hands each DC pools of Relative IDs used to build new SIDs for users, computers, and groups.

If it is offline long enough that RID pools exhaust, that DC cannot create new security principals.

Short outages are fine. Multi-day outages plus a hiring/build surge are not. Confirm every DC has a RID pool.
Domain FSMO

Infrastructure Master

NW-DC01.northwind.lab

Updates cross-domain group-to-user references (phantoms) so memberships stay consistent.

In a single-domain forest this role is effectively idle. In multi-domain forests it matters.

Do not place it on a GC unless every DC in the domain is a GC (the usual modern design).
Sites are how AD thinks about the network

A site should be a set of well-connected subnets. Clients in those subnets find a local DC. Site links (cost + interval) decide how often DCs across WAN links pull changes. Empty leftover sites and missing subnets are the usual mess.
